# 版本规则

当前从 `v1.0.0` 开始建立正式版本体系，采用语义化版本（SemVer）：
- `MAJOR.MINOR.PATCH`

## 含义
- `MAJOR`：存在破坏性变更，或需要用户/运维明显改变使用方式
- `MINOR`：新增功能、明显 UI 优化、一次完整能力提升
- `PATCH`：小修复、小范围样式调整、文档修正、非破坏性维护

## 本项目约定
- `v1.0.0`：稳定基线 + 正式文档体系建立完成
- 明显功能或整轮 UI / 性能优化，升次版本号，如 `v1.1.0`
- 小修复、文档修正、非破坏性维护，升修订号，如 `v1.1.1`
- 历史正式版本说明保留在 [release-notes.md](release-notes.md)，不因回滚或重名而删除历史版本记录

## 每次正式发版需要同步的内容
1. `package.json` 中的 `version`
2. [release-notes.md](release-notes.md) 中的版本说明
3. push 到 `main` 后由 GitHub Actions 在部署成功后自动创建对应 tag，例如 `v1.0.2`

## 日常提交与正式版本的区别
- 日常提交：正常 commit / push，可自动部署，但不一定形成正式版本节点
- 正式版本：在完成正常提交基础上，同步更新版本号与版本说明；部署成功后会自动补齐同版本 tag
